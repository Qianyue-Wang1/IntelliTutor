# IntelliTutor：机器学习连续学习实验平台

这是一个供参与者**在本机自助完成一次或多次机器学习连续学习实验**的 Docker Compose 项目。正常实验不需要管理员逐阶段推进，也不要求参与者创建账号或设置密码：参与者只填写姓名和手机号，按固定顺序完成实验，并在结束后下载自己的 Excel 数据文件。

> 本仓库的运行内容是“无监督学习到大模型自监督预训练”五轮连续学习实验。它不是通用的在线教学平台，应用不训练或加载 LoRA、Adapter；文本推理由独立的本地 vLLM 服务承担。

## 参与者实际流程

1. 在首页填写姓名和手机号，系统新建一条独立实验记录。
2. 选择并锁定一种实验模式：`Basic Tutor`、`Full Tutor`、`Direct LLM` 或 `No AI`。
3. 按顺序完成 M1–M5；每轮学习结束后完成三道小后测。
   - Basic/Full：每轮可选择逐步讲解或自由研讨。
   - Direct LLM：围绕本轮主题学习，并最多进行三轮追问。
   - No AI：阅读固定讲义后进入小后测。
4. 完成后测与完成凭证后，打开“本机实验记录”，下载对应完成记录的 Excel 文件。

未完成记录会保留，便于返回继续；它们不能导出。选择“从头开始一次新实验”只会新建记录，不会覆盖既有记录。不同实验记录的数据彼此隔离。

## 导出的研究数据

完成记录导出为一个 Excel 工作簿，工作表分别保存：

- 参与者与实验记录标识、开始/完成时间、模式与完成状态；
- 五轮小后测、后测的题目正文、选项、作答、正确性与用时；
- Basic/Full 子步骤中的客观题作答与判定；
- 学生侧交互与行为事件（如进入页面、翻页/滚动、点击、窗口可见性变化、提交、超时）；
- Tutor 运行的必要过程指标与实验事件时间线。

导出文件不包含模型提示词、模型回复全文、内部教学规划、学习画像、答案键或模型内部推理。学生应在完成后自行下载并按研究安排提交该 Excel 文件；数据库数据保留在其本机 Docker 数据卷中，不会自动传回研究者电脑。

## 快速开始

完整的 Windows + Docker Desktop 安装、代理配置、环境变量、启动、排错和更新流程见：[本地部署手册](docs/本地部署手册.md)。

已安装 Docker Desktop 后，最短的启动路径是：

```powershell
Copy-Item .env.example .env
# 编辑 .env：替换所有 CHANGE_ME 值，配置本地 vLLM 地址、密钥和模型名，并设置 EXPERIMENT_MODE=true
docker compose up -d --build
docker compose ps
```

所有服务显示 `healthy` 后访问 [http://localhost/](http://localhost/)。首次构建需要下载镜像与依赖；若 Docker 报 EOF、TLS 或镜像超时，应先检查网络、Docker Desktop 代理和镜像设置。

## 本地模型与并发

三张 A800 80GB 每卡加载一份 Qwen3-32B FP16，使用 vLLM DP=3、TP=1 的统一接口。Direct、Basic、Full 共用三个副本，所有文本请求只走配置的 vLLM 服务。部署脚本、初始参数、升级注意事项和压测方法见 [vLLM 三卡部署与并发验证](docs/vLLM三卡部署与并发验证.md)。

Python 使用单进程、受控线程池与会话互斥；Java 推理消费者初始并发 6、最大 12。不要直接增加 Python worker 数量。Qwen3-32B 为文本模型，未配置视觉模型时图片接口不可用。

## 运行边界

- `Full Tutor` 从第二轮起使用该参与者此前轮次产生的结构化学习状态；`Basic Tutor` 只使用当前轮上下文。
- Direct LLM 只作为知识讲解与问答导师，不显示内部提示词；No AI 不调用 AI。
- 正式测试页面不调用 AI，也不把答案键提前发给前端。
- 正常参与者流程不需要管理员。保留的管理员入口仅用于本地异常处理、查看或导出，不应用于推进学生的正常实验流程。

## 目录说明

- `web/`：React 前端、参与者实验流程与导出入口。
- `backend/`：Java API、实验状态、评分、行为日志与 Excel 导出。
- `python/`：讲解、研讨与结构化学习状态服务。
- `backend/src/main/resources/db/migration/`：数据库初始化与演进脚本，必须随代码发布。
- `miniapp/`：会随 Web 镜像构建的 H5 前端，必须随源码发布。
- `deploy/`、`docker-compose.yml`：容器构建、反向代理与服务编排。
- `docs/本地部署手册.md`：供参与者使用的部署与故障排查手册。

`frontend/` 和离线研究目录不属于当前 Docker 实验流程；不要因发布本地实验而删除它们，但也不应把它们当作参与者部署所需组件。`miniapp/` 例外：它是当前 Web 镜像构建的一部分。

## 开发与发布前检查

```powershell
# 配置语法检查（不会启动服务）
docker compose config --quiet

# 查看运行状态和近期错误
docker compose ps
docker compose logs --since 10m backend web python
```

不要对已有参与者数据执行 `docker compose down -v`；该命令会删除 Docker 数据卷，从而清空本地实验记录。

准备把项目发布到 Git 仓库前，请阅读下方“仓库发布准备”并使用干净目录完成一次从克隆到启动的验证。

## 仓库发布准备

必须提交运行所需的源码、Docker 配置、数据库迁移、依赖清单、`.env.example` 与本 README/部署手册；绝不提交真实 `.env`、API Key、密码、Docker 数据卷、参与者数据或本机构建产物。根目录 `.gitignore` 已覆盖这些常见本地文件，但首次初始化仓库后仍应在提交前逐项检查待提交列表。

建议发布者先创建一个新的、干净的 Git 仓库副本，只加入本 README 中列出的运行目录与配置。提交前使用 `git status` 核对改动，不提交运行数据和密钥。

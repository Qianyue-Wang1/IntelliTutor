# 交互式学习实验平台：Windows 本地部署与使用手册

本手册面向参与者或现场工作人员，在 Windows 电脑上部署 IntelliTutor 并完成机器学习连续学习实验。**一套部署可供多名参与者先后使用**；每一次实验记录彼此隔离。

参与者填写姓名和手机号后，按顺序完成前测、模式选择、M1–M5 五轮学习、每轮小后测和最终后测，再自行下载 Excel 数据。


## 1. 开始前确认

### 电脑、网络与材料

- Windows 11 64 位；建议至少 8 GB 内存和 20 GB 可用磁盘空间。
- 能连接互联网
- 已取得完整项目文件夹，至少包含 `docker-compose.yml`、`.env.example`、`deploy`、`backend`、`python`、`web` 和 `miniapp`。其中 `miniapp` 会参与 Web 镜像构建，缺少它会导致首次构建失败。
- 80 和 443 端口没有被其他软件占用；服务启动后通过 <http://localhost/> 访问。
- 已取得可用的 LLM API 地址、密钥和模型名 (见LLM API获取手册）。没有 LLM 配置时，Basic Tutor、Full Tutor 和 Direct LLM 不能完成。

本项目运行 Linux 容器，不需要本地 GPU、Python、Java、Node.js、本地大模型、LoRA、Adapter、torch、transformers 或 peft。

### 不要删除或泄露的内容

- 不要把 `.env`、API 密钥、Docker 数据卷或参与者下载的 Excel 发给无关人员。
- 不要执行 `docker compose down -v`、`docker volume prune` 或 Docker Desktop 的“清理全部数据”；这些操作会删除数据库卷，未导出的记录无法恢复。
- 不建议将项目放在 OneDrive、WPS 云盘等自动同步目录，建议本地路径为 `D:\intellitutor\intellitutor-main`。

## 2. 安装并设置 Docker Desktop

### 2.1 安装 WSL 2

1. 以**管理员身份**打开 PowerShell。
2. 执行：

   ```powershell
   wsl --install
   ```

3. 按提示重启电脑。重启后再次以管理员身份打开 PowerShell：

   ```powershell
   wsl --update
   wsl --version
   ```

如果提示虚拟化未开启，请在 BIOS/UEFI 中开启 CPU Virtualization（Intel VT-x、AMD-V 或 SVM），再重复以上步骤。

### 2.2 安装 Docker Desktop

1. 从 Docker 官方页面下载 Docker Desktop：<https://docs.docker.com/desktop/setup/install/windows-install/>。
2. 双击安装程序。个人/教学电脑通常选择默认的**按用户安装**和 **Use WSL 2 instead of Hyper-V**。
3. 安装结束后启动 Docker Desktop，首次启动时接受服务条款。不用注册账户即可使用
4. 等待 Docker Desktop 左下角显示 Engine running / 正在运行。本项目只使用 Linux 容器；如菜单中有“Switch to Linux containers”，请选择它。

### 2.3 验证 Docker

关闭管理员 PowerShell，重新打开普通 PowerShell：

```powershell
docker version
docker compose version
docker run --rm hello-world
```

最后一条应输出 Docker 的欢迎信息。若出现“cannot connect to the Docker daemon”，请启动 Docker Desktop，等待 Engine running 后重试。

## 3. 准备项目与配置

### 3.1 放置并检查项目

将完整项目解压或复制到本机，例如：

```text
D:\intellitutor\intellitutor-main
```

打开普通 PowerShell：

```powershell
cd D:\intellitutor\intellitutor-main
Get-ChildItem docker-compose.yml, .env.example
```

两项都能列出后再继续。若实际路径不同，请替换后续命令中的路径。

### 3.2 创建本机 `.env`

首次部署仅执行一次：

```powershell
Copy-Item .env.example .env
notepad .env
```

在打开的 `.env` 中保存以下本机设置：

```dotenv
SITE_ADDRESS=localhost
PUBLIC_ORIGIN=http://localhost
TZ=Asia/Shanghai
EXPERIMENT_MODE=true
```

`EXPERIMENT_MODE` 位于 `.env.example` 文件末尾。复制到 `.env` 后，请将示例值 `false` 改为 `true`。

将以下所有 `CHANGE_ME...` 替换为各不相同的随机强密码。建议只使用大小写字母和数字，避免空格、引号、`$` 等容易被 Compose 解释的字符：

```dotenv
POSTGRES_PASSWORD=自行设置的数据库密码
REDIS_PASSWORD=自行设置的Redis密码
RABBITMQ_PASSWORD=自行设置的RabbitMQ密码
NEO4J_PASSWORD=自行设置的Neo4j密码
JWT_SECRET=至少64个随机字符的JWT密钥
```

可在 PowerShell 生成随机十六进制字符串，再复制到 `.env`：

```powershell
-join ((1..64 | ForEach-Object { '{0:x}' -f (Get-Random -Maximum 16) }))
```

`EXPERIMENT_ADMIN_ACCOUNT` 与 `EXPERIMENT_ADMIN_PASSWORD` 是兼容保留的管理员配置，不是参与者完成本地实验的入口。若保留默认变量，请把管理员密码改为至少 12 位的非默认值。

其余未标有 `CHANGE_ME` 的基础设施变量可保持 `.env.example` 的默认值。不要删除变量名；空值或拼写错误可能导致 Compose 启动失败。

### 3.3 配置 LLM API

本实验的 Basic Tutor、Full Tutor 和 Direct LLM 模式需要调用大模型 API。参与者应自行申请阿里云百炼**通用 API Key**，并确认对应模型有可用免费额度。请先按[阿里云百炼 API Key 申请与配置指南](阿里云百炼API-Key申请与配置指南.md)完成账号开通、API Key 创建及“免费额度用完即停”设置，再返回本节。

在项目根目录的 `.env` 文件中找到 `QWEN_` 变量，按以下示例配置：

```dotenv
QWEN_API_URL=https://dashscope.aliyuncs.com/compatible-mode/v1/
QWEN_API_KEY=粘贴你自己的百炼通用APIKey
QWEN_MODEL_INSTRUCT=qwen-plus
QWEN_MODEL_LARGE=qwen-plus
QWEN_MODEL_SMALL=qwen3-8b
QWEN_MODEL_VL=
QWEN_MODEL_VLFAST=
QWEN_MODEL_REASONING=qwen-plus
```

**只需将 `QWEN_API_KEY` 后面的示例文字替换为自己申请的真实 API Key**。请使用指南要求的**华北 2（北京）**地域；API 地址及模型配置按上述实验统一配置保留，不要自行替换模型，也不要混用其他服务商的配置。如指定模型不可用或没有免费额度，请联系实验发起人确认，不要自行更换。

API Key 只应保存在本机 `.env` 中，不要上传到代码仓库、填写到前端页面或发送给他人。常规实验不依赖本地视觉模型；`IMAGE_INPUT_ENABLED=false` 时，不必配置视觉模型变量。若 API Key 无效或额度耗尽，即使容器启动成功，AI 教学或判题仍可能失败。

保存后先检查 Compose 是否能读取配置：

```powershell
docker compose config --quiet
```

没有输出且命令返回提示符，表示必填配置格式可被读取；该命令不验证 API 密钥有效性。

## 4. 首次构建与启动

在项目根目录执行：

```powershell
docker compose up -d --build
docker compose ps
```

第一次可能需要数分钟。等待到 `postgres`、`redis`、`rabbitmq`、`neo4j`、`python`、`backend`、`web` 显示为 `healthy` 或 `Up`；其中 `python`、`backend`、`web` 必须为 `healthy`。

尚未完成时，等待约 30 秒后再执行：

```powershell
docker compose ps
```

若服务失败，先收集日志，**不要清理卷**：

```powershell
docker compose logs --since 15m backend python web
```

### 4.1 网络代理或镜像下载失败

首次构建会下载 PostgreSQL、Redis、RabbitMQ、Neo4j、Python、Java 和前端镜像。若出现 `EOF`、`TLS handshake timeout`、`i/o timeout` 或 `failed to pull`，通常与网络或代理有关。

1. 确认浏览器能访问 Docker Hub 和所用 LLM 服务商。
2. 使用 Clash 等代理时，在 Docker Desktop 打开 **Settings → Resources → Proxies**：
   - 选择 Manual configuration；
   - HTTP 与 HTTPS 两栏均填写当前代理实际地址，例如 `http://127.0.0.1:7897`；端口以当前代理客户端显示为准，可在 Clash 的设置中查看；
   - 容器代理选择 Same as host proxy；
   - 点击 Apply & Restart。
3. 如曾设置 registry mirror，且日志显示该镜像源超时，可在 Docker Desktop 的 Docker Engine 设置中移除失效 mirror，Apply & Restart 后重试。
4. 回到项目根目录重试：

   ```powershell
   docker compose build --pull=false
   docker compose up -d
   ```

如果构建仍报错或速度很慢，可参考[构建故障与解决方案汇总](构建故障与解决方案汇总.docx)，按具体错误修改对应服务 Dockerfile 中的镜像源配置。

## 5. 打开并完成实验

### 5.1 首次访问

在部署电脑的浏览器打开 <http://localhost/>。

看到“开始实验”以及姓名、手机号输入框，说明进入正确入口。无需访问 `/register`、`/login` 或管理员页面。浏览器曾登录旧版本系统时，可使用无痕窗口，或清除 `localhost` 的站点数据后重新打开首页。

### 5.2 参与者操作顺序

1. 输入姓名和手机号，点击“开始实验”；两项仅用于识别本机历史记录，不需要密码。
2. 独立完成前测。
3. 按研究人员提供的线下名单选择 Basic Tutor、Full Tutor、Direct LLM 或 No AI。确认后该条记录不能更换模式。
4. 依次完成 M1–M5：
   - Basic Tutor / Full Tutor：每轮选择逐步讲解或自由研讨，完成教学后进入三道小后测；
   - Direct LLM：阅读讲解，可进行最多三次追问，再进入小后测；
   - No AI：完整阅读固定讲义、滚动至底部后进入小后测，不得使用 AI。
5. 完成最终后测。
6. 查看完成凭证，再点击“查看记录与导出数据”。
7. 在“本机实验记录”找到有完成时间的记录，点击“下载数据 Excel”，并按研究组织者要求手动提交下载的 `.xlsx` 文件。

只有完整完成的记录可以导出。Excel 含参与者标识、题目与测试作答、Basic/Full 子步骤客观作答、学生交互和页面行为事件等多个工作表；不会导出模型提示词、内部教学规划、学习画像或答案键。

### 5.3 中断、继续与重新开始

- 中途关闭浏览器、断电或退出后，不要新建记录。重新打开 <http://localhost/>，填写原姓名和手机号，在出现的入口选择历史记录或继续当前实验。
- 要重新完整做一次时，在“本机实验记录”点击“从头开始一次新实验”。系统会新建独立记录，不会覆盖已有记录。
- 未完成记录会保留以便继续，但不能导出，避免和正式完成数据混淆。

## 6. 日常操作

### 暂停与恢复

暂停服务但保留数据：

```powershell
docker compose stop
```

下次恢复：

```powershell
cd D:\intellitutor\intellitutor-main
docker compose up -d
docker compose ps
```

### 查看服务状态和日志

```powershell
docker compose ps
docker compose logs --since 10m backend python web
```

只查看单个服务：

```powershell
docker compose logs --since 10m python
docker compose logs --since 10m backend
```

### 更新收到的新版本

先确保所有已完成参与者都导出了 Excel。项目文件更新后，在根目录执行：

```powershell
docker compose build --pull=false
docker compose up -d --wait --force-recreate
docker compose ps
```

后端需要的数据库迁移会在启动时自动执行；启动过程中不要关闭 Docker Desktop。

## 7. 常见问题

### 无法连接 Docker

Docker Desktop 尚未启动或还在初始化。启动 Docker Desktop，等待 Engine running 后再运行命令。

### 拉取镜像出现 EOF、TLS 或超时

这是网络/代理问题。按第 4.1 节检查 Docker Desktop 的 Proxy 和 registry mirror，然后重试：

```powershell
docker compose build --pull=false
docker compose up -d
```

不要因镜像下载失败修改 Dockerfile 或删除数据卷。

### 浏览器无法访问 `http://localhost/`

依次执行：

```powershell
docker compose ps
docker compose logs --since 10m web backend python
```

若 `web` 未运行：

```powershell
docker compose up -d --build web
```

若 80 端口被占用，以管理员身份打开 PowerShell：

```powershell
Get-NetTCPConnection -LocalPort 80 -ErrorAction SilentlyContinue
```

先关闭占用端口的软件。不要随意修改 Compose 端口映射，否则 `PUBLIC_ORIGIN` 与浏览器地址也需同步修改。

### 页面空白、进入旧登录页或看不到历史记录

使用无痕窗口测试；仍有问题时，清除浏览器中 `localhost` 的 Cookie 与站点数据，再打开 <http://localhost/>。参与者入口只有姓名和手机号，不需要密码。

### AI 页面报错、提交选项后等待很久或无法继续

不要反复刷新或更换模式。执行：

```powershell
docker compose ps
docker compose logs --since 15m python backend
```

确认 Python、backend 为 healthy；再核对 `.env` 中 API 地址、密钥、模型名和代理。可以安全重启 AI 服务：

```powershell
docker compose up -d --force-recreate python backend
```

重启后回到首页，用相同姓名和手机号恢复当前实验。仍失败时，保存日志、截图和发生时间给维护人员。

### 关闭或迁移系统

正常关闭：

```powershell
docker compose stop
```

迁移到另一台电脑前，先让每位已完成参与者下载并提交 Excel；然后由维护人员备份 Docker 卷和 `.env`。不要只复制项目文件夹，数据库数据不在该文件夹中。

## 8. 使用前检查清单

- [ ] Docker Desktop 已启动，`docker compose ps` 中 `python`、`backend`、`web` 均为 healthy。
- [ ] 浏览器能打开 <http://localhost/>，并显示姓名和手机号入口。
- [ ] LLM API 已由维护人员验证；若参与者自行部署，已明确 API 密钥来源、额度和保管责任。自行部署者能够访问本机 `.env`，因此不要提供个人长期密钥。
- [ ] 80/443 端口未被其他软件占用。
- [ ] 已告知参与者：选择模式后不能更换；测试须独立完成；完成后必须下载 Excel。
- [ ] 已准备好收集 Excel 文件的方式。

## 9. 给维护人员的故障信息模板

发生问题时，请记录而不要删除数据：

```text
发生时间：
浏览器页面/地址：
所选模式与轮次：
报错文字或截图：
docker compose ps 输出：
docker compose logs --since 15m python backend web 输出：
```

这些信息足以定位大部分部署、网络、LLM 调用和页面流转问题，同时不会暴露参与者的完整作答内容。 **如果遇到任何手册中没有提到的问题，都请及时在QQ群里联系实验发起人**
